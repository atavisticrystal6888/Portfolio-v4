## Problem

Every task manager makes the same bet: to be used, it must be seen, so it floats, badges and notifies. Checking your tasks becomes another context switch.

The gap: a task list that is there when you glance at the desktop and gone while you work, with no window, dock icon or account to manage.

## Users

Desktop users on Windows and macOS who keep a short running list and want it visible without it asking for attention. There was no user study behind DeskTasks; I built it for myself first. The plan came from one observation and one rule.

The desktop wallpaper is glanced at dozens of times a day without meaning to. A widget pinned behind every window inherits that attention without asking for it.

The rule: a local-first product is only trustworthy if it never loses a task and never quietly changes one. Never approximate.

## Decision

<Decision>
Pin the widget behind every window rather than on top of them. Everything else follows from refusing attention: accountless, local-first, no dock icon.
</Decision>

The second decision came later, in September 2026: freeze the hosted Supabase line at v1.3.1 and move the main line to sync over the user's own Wi-Fi, with the widget itself acting as the hub. A local-first product that needs a hosted database to reach your phone was carrying a server it did not need. The Supabase path is frozen, not deleted, and still documented.

## Trade-offs

**Local-first, accountless.** Data lives in one portable JSON file; the product is complete without a network.

**Capture is one line.** `pay rent tomorrow 4pm !high #home every month` becomes a titled, tagged, scheduled, prioritised, recurring task.

**Never approximate.** A calendar rule that cannot round-trip honestly imports as a clearly labelled single task or exports with an explaining note, instead of silently drifting.

## What shipped

The panels in the header image (select it to open full size) show the pinned list, quick-add turning one line into a dated, timed and tagged task, and a filtered search.

Capture is one line; the parser reads date, time, priority, tag and recurrence out of it, so a task never needs a form. Reminders come as toast notifications with repeat nudges, a morning summary and an end-of-day recap. One timer runs at a time, and completion banks the time.

Two release lines exist side by side:

- **Hosted line, v1.3.1** (tags v1.3.0 and v1.3.1, 8 to 9 Sep 2026). Windows and macOS builds plus a companion PWA that syncs through Supabase when the user opts in. Frozen in Sep 2026. The hosted PWA is live at [task-manager-one-sandy-94.vercel.app](https://task-manager-one-sandy-94.vercel.app/) (HTTP 200 on 30 Sep 2026).
- **Main line, v2.0.0-alpha.9** (latest commit 19 Sep 2026). The same widget, but the phone app loads from the widget over the local network and syncs with no server at all.

Other shipped pieces: three import/export formats (.ics with RRULE, CSV with BOM, Markdown), zero telemetry, zero accounts, and a data file that is portable by hand. Widget and phone share one parser, so they cannot disagree about what "biweekly" means.

<UnderTheHood title="Architecture and implementation">

**Single writer.** The Electron main process owns all state: every mutation goes through IPC to one store, and the renderer re-renders from a single broadcast. UI and disk can never disagree, which is what makes crash recovery boring.

**Storage.** One portable JSON file with atomic writes (temp file, fsync, `.bak`, rename), 7 daily snapshots and automatic corruption recovery with a visible banner.

**Parser.** Relative times, ranges, day words and recurrence, including `last friday of month` and `every N days after done`.

**Z-order.** On Windows the widget is pinned with `HWND_BOTTOM`; a once-per-second check keeps it there through Win+D. A wallpaper-layer reparenting mode is more robust but trades focus. On macOS Electron offers no window level below normal, so DeskTasks floats like Stickies, and focus detection leans on a best-effort OS file, documented as fragile.

**Links.** Notes allow only `http`, `https` and `mailto`; `file:`, `shell:` and `javascript:` are refused outright.

**Companion PWA.** Vite, IndexedDB and a service worker, reusing the shared modules (parser, recurrence, dates, CSV). On the v1.3 line it syncs through a single Supabase `records` table when the user opts in; on the v2 alpha it is served by the widget's local hub over HTTPS after a QR pairing step.

**Formats.** `.ics` with RRULE, CSV with BOM, Markdown; UID-based dedupe on re-import. A "2nd Tuesday" rule the engine cannot represent, or "after done" recurrence with no calendar equivalent, imports as a labelled single task or exports with a note.

</UnderTheHood>

## Validation

Reliability was tested rather than assumed. The acceptance gate recorded in the project roadmap ran on 15 Sep 2026, on the debug-sweep tree over commit `1feaa5a` plus the hub branch (so before the last v2 alpha commits of 19 Sep), with zero failures:

- **Logic:** 531 tests
- **Sync:** 206 tests, plus 177 sync-transport tests
- **Companion PWA suites:** list 20, store 202, editor 76
- **End-to-end:** 271 tests that restart the real app to prove persistence and crash recovery, asserting on renderer state and on the bytes on disk

Those counts are from that dated run, not a promise about the next one.

## Limits and next

- **No usage data.** Zero telemetry means I cannot say how many people run DeskTasks. The evidence is that the product survives its own tests and that tagged builds shipped on two platforms.
- **The hosted line is frozen.** v1.3.1 still works but is not the path to pick for a new setup; the v2 line is still an alpha.
- **Licence.** `package.json` declares MIT, but the repository has no LICENSE file yet, and the repository is private.
- **Next bet:** a code-signing certificate. Unsigned builds are the real adoption tax and matter more to first-run experience than the next feature.
- **Open question:** whether wallpaper-layer reparenting can become the Windows default; its focus-loss trade-off needs a cleaner answer.
